## What the historical sources establish

The sponsor source includes a six-key evidence envelope, compliance and owner-decision gates, a renderer that refuses blocked targets, a validator and a dashboard backed by run packets. Its client materials remain supplied claims, not independent verification. Campaign details here are attributed to text extracts and structured source packets; the PDF and PPTX were not independently re-extracted for this handbook. September 2026 campaign dates are historical, not an invitation to sell current inventory.

HubSpot Agent CLI Skills is a skills collection, not a Pipedrive client or the implementation of a CLI. Its commands, edition assumptions, workflow interfaces and confirmation semantics are not portable to Pipedrive. The Pipedrive pages are an adaptation with newly written provider-specific guidance, not an upstream Pipedrive recipe or evidence of a verified adapter.

The installation repository's inspected tree has three text files: a README, setup guide and macOS installer. It is a distribution wrapper, not a tracked orchestration engine. Provider consent and recurring-runner restrictions are instructions, not demonstrated runtime enforcement. The release archive and packaged runtime were not inspected or launched for this handbook.

## Fixture and execution provenance

The offline `fixtures/sponsor-crm.json` contains synthetic organisations, persons, deals and local associations. Category archetypes and package labels derive from the cited sponsor source; identities and amounts are invented. Fixture keys and associations are not live Pipedrive identifiers or API payloads. See [seed mapping](/docs/guides/seed-data).

The local automation module demonstrates deterministic planning and tenant-bound approval without live writes by default. The optional Deepline adapter is documented but not live-verified. Production needs separately authorised execution, a durable replay ledger and read-back reconciliation. Passing offline tests proves only the tested local behaviour; see [safe writes](/docs/guides/safe-writes) and [local development](/docs/reference/local-development).

These summaries are practical reuse guidance, not legal advice.
