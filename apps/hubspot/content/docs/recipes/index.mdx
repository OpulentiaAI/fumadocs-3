Choose one outcome before you choose a tool. These recipes adapt the source showcase into a CRM setting without treating research, an outreach draft and a live send as interchangeable.

| Recipe                                                       | Input                                                  | Result                                     | Stops before                            |
| ------------------------------------------------------------ | ------------------------------------------------------ | ------------------------------------------ | --------------------------------------- |
| [CRM account brief](/docs/recipes/crm-brief)                 | A company identity and an authorised CRM lookup        | A cited account brief with unknowns        | Any CRM mutation or outreach            |
| [Sponsor qualification](/docs/recipes/sponsor-qualification) | The historical campaign context and candidate evidence | A qualification decision and review packet | Claiming a budget or sponsor commitment |
| [Review-ready outreach](/docs/recipes/review-ready-outreach) | An approved account and grounded context               | A draft for human review                   | Sending or enrolling anyone             |

## Before any live run

Use a test portal and synthetic records first. Resolve the target record identity, inspect the available properties, define who approves changes and record what a successful outcome looks like. A source-verified command example is not a runtime-tested integration.

See [safe CRM writes](/docs/guides/safe-writes) for the write boundary and [the CLI reference](/docs/reference/hubspot-cli) for commands verified against the skills repository.
