Source: [Deepline DataForSEO guide](https://deepline.com/docs/guides/dataforseo-via-deepline). Source and HubSpot documentation read: 2026-10-18.

This is an offline implementation plan with no live HubSpot execution and no DataForSEO requests or purchases. Its useful output is a dated company research summary, not an automatic lead score or a list of people to contact.

## Deepline-specific behaviour versus HubSpot adaptation

The source describes DataForSEO discovery and execution through Deepline CLI and MCP tooling, including keyword research, search-result analysis, backlinks and domain metrics. It also describes managed credentials, bring-your-own-key arrangements, operation receipts and workspace database access. Those are Deepline-side claims, not HubSpot capabilities. Verify current operation contracts, provider terms and prices independently before use; this adaptation does not repeat the source's billing promises as established facts.

The HubSpot adaptation is deliberately narrower: resolve a company, attach a research reference and expose a small set of reviewed metrics. HubSpot's [companies API](https://developers.hubspot.com/docs/api-reference/legacy/crm/objects/companies/guide) documents company property reads and updates. It does not make DataForSEO available natively or establish an automatic connection to Deepline's database. No source commands or code are reproduced here.

## Prerequisites and licensing

Obtain authority to run the selected provider operations and retain their results. Agree a query budget, geography, language, search engine, device context and collection date before commissioning research. An administrator must approve the HubSpot company mapping and integration scopes. Keep third-party credentials outside CRM fields.

Custom company properties require account capacity and permission. If implementing enrichment inside a HubSpot custom code action, [workflow actions](https://knowledge.hubspot.com/workflows/choose-your-workflow-actions) lists that action for Data Hub Professional and Enterprise. An external research worker avoids relying on that action but still needs its own hosting, provider contract and authorised CRM access. Do not assume marketing content tools, workflow tiers or data credits are interchangeable licences.

## Choose a research contract

Separate four different questions. Keyword metrics support content prioritisation; a search-result snapshot identifies visible pages; backlink data describes links under a provider's measurement model; domain estimates describe a site, not necessarily the legal entity or its spending power. Decide which question is actually useful for the account team before collecting all four datasets.

Use HubSpot company `domain` and record ID as matching inputs, with manual exceptions for parent groups, regional sites, agencies and product microsites. Proposed custom properties might be `ops_seo_research_state`, `ops_seo_observed_at`, `ops_seo_market` and `ops_seo_brief_url`. These names must be created and validated against the [Properties API](https://developers.hubspot.com/docs/api-reference/legacy/crm/properties/guide). Keep the detailed keyword and result rows outside HubSpot, preserving units and query dimensions there.

## Implementation steps

1. **Resolve the account.** Start from an existing company ID or search company records by a normalised domain. If several records plausibly represent the site, stop for review. Do not create a new company simply because a subdomain differs from the existing account's primary domain.
2. **Specify collection dimensions.** Record the exact domain or page target and the intended market. Two rankings collected for different countries are not a trend. Store query time and any provider observation time separately, and retain the original metric definitions.
3. **Collect a bounded research sample.** Run only authorised operations after checking their current contract. Preserve receipts and request identities. Reuse a permitted recent dataset only when its dimensions and freshness match the new question; do not assume Deepline automatically caches or deduplicates requests.
4. **Write a restrained brief.** Summarise relevant observations, their limitations and a possible account conversation. Describe traffic as an estimate where applicable. A competitor appearing above the account for one query does not establish that the account is losing customers or actively shopping.
5. **Propose the CRM handoff.** Present the company ID, brief reference, observation date and candidate properties for review. Preserve `hubspot_owner_id`, lifecycle state and deal values. A contact-to-company association is a separate CRM relationship; a person found on a ranking site must not be attached to an account automatically.
6. **Verify an approved update.** Retrieve the company by its saved ID and compare the exact written values and link. HubSpot [CRM Search](https://developers.hubspot.com/docs/api-reference/latest/crm/search-the-crm) documents indexing delay, so immediate search visibility is not the right proof of a successful update.

## Approval boundary

Research collection needs an approved budget and data-use purpose. CRM writes need an approved field mapping. Any new audience, personal-data enrichment, contact association, outbound message or sequence enrolment is a separate approval boundary. This plan does not authorise the source guide's broader prospecting chain merely because it is technically imaginable.

## Failure handling

Treat missing metrics as unknown, not zero. Keep provider errors distinct from a real absence of backlinks or rankings. On an ambiguous result after submission, reconcile the provider receipt before buying the same query again. If a CRM handoff fails, retain the completed research and retry only the handoff after diagnosis. Version briefs rather than replacing a newer market snapshot with a late-arriving older one.

## Validation and acceptance

Use fixtures for one company with several domains, two markets, a missing metric, a changed domain and a duplicate collection event. Confirm that every published number has a unit, dimension, time and source reference, and that no metric silently alters ownership or qualification. Accept only a readable, correctly associated company brief whose uncertainty survives the CRM summary. The intended success measure is useful reviewed account context per research cost, not the number of provider calls.
