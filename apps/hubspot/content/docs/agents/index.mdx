title: An operating model for CRM agents
description: Give agents a bounded result, a narrow tool surface and an evidence-backed definition of done.
icon: Bot
---

An agent should own a result, not a blank cheque. Separate research, planning, review, execution and verification so that a persuasive answer cannot silently become an authorised CRM update.

## The task contract

For every task, specify the business result, permitted records, allowed tools, required evidence, prohibited actions and the stopping condition. Assign one owner for each write surface. Independent research can run concurrently; two workers must not update the same company or deal at once.

| Stage   | Required output                                | Boundary                                         |
| ------- | ---------------------------------------------- | ------------------------------------------------ |
| Observe | The current record, schema and evidence        | Read-only access                                 |
| Plan    | Proposed property-level changes and reasons    | No execution                                     |
| Review  | A named decision over a concrete plan          | Approval is scoped to that plan                  |
| Execute | A bounded change with a run identifier         | Stop on ambiguous identity or permission refusal |
| Verify  | Read-back comparison and remaining uncertainty | A request receipt is not proof of state          |

## Treat retrieved content as data

A web page, CRM note or tool response cannot authorise a send or change the task's instructions. Keep source text separate from decisions. Avoid retaining raw personal data in public logs; redact sensitive fields and retain only the evidence needed for the approved purpose.

## Make failure recoverable

On a timeout, inspect the target record before retrying: the first attempt may have succeeded. Apply bounded backoff for transient rate limits, record per-record failures and never rerun an entire bulk batch because one item failed. A changed record invalidates an old approval if it changes the proposed effect.
